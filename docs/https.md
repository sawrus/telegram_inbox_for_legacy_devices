# Необязательный HTTPS в домашней сети

По умолчанию сервис работает по HTTP. Для шифрования можно добавить локальный HTTPS-прокси и установить доверие к
созданному локальному центру сертификации на iPad. Сертификат привязан к IPv4-адресу сервера; закрепите этот адрес на
роутере. Доступ по другому адресу не пройдёт проверку сертификата.

На сервере, из каталога проекта, укажите фактический постоянный IP:

```sh
sudo sh scripts/create_local_tls.sh 192.168.1.10
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

Скрипту нужны Python 3 и OpenSSL. Он не перезаписывает существующий каталог `data/tls`. Ключи `ca.key` и `server.key`
секретны: не копируйте их на iPad и не передавайте другим людям. Если они скомпрометированы, удалите доверие к старому
центру на устройствах и создайте новые сертификаты. Сертификат сервера действует 397 дней; после окончания срока
переместите старый каталог в безопасное место, заново выполните скрипт и установите новый сертификат центра на iPad.

Перенесите **только** `data/tls/ca.crt` на iPad по доверенному каналу, например через AirDrop с принадлежащего вам
устройства. Убедитесь, что это именно созданный вами сертификат. Откройте файл и установите профиль сертификата в
настройках. Затем в «Настройки → Основные → Об этом устройстве → Доверие сертификатам» включите полное доверие к
`Telegram Inbox Local CA`. Названия пунктов могут немного отличаться в зависимости от языка iOS 12. Откройте в Safari
`https://192.168.1.10:8443`, подставив свой IP, и войдите с теми же учётными данными.

Обычный HTTP-порт 8080 при этом остаётся доступен, как и в базовой конфигурации. Используйте адрес HTTPS на устройствах,
где установлено доверие: обращение к HTTP не шифрует пароль или содержимое. Для отключения HTTPS удалите сервис прокси
командой `docker compose -f docker-compose.yml -f docker-compose.https.yml down`, затем запустите основной сервис
обычной командой `docker compose up -d`. Удалите доверие к локальному центру с iPad, когда оно больше не нужно.
