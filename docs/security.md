# Безопасность и обновление

Приложение предназначено для доверенной домашней сети. HTTP Basic защищает доступ паролем, но HTTP передаёт
пароль, сообщения и фотографии без шифрования. Не открывайте порт в интернет; для шифрования настройте
[необязательный HTTPS](https.md).

Задайте непустые `INBOX_USERNAME` и `INBOX_PASSWORD` в `.env`. Используйте длинный случайный пароль; двоеточие в
имени не допускается. Изменение пароля требует пересоздания контейнера (`docker compose up -d`); браузерам потребуется
войти заново. Без учётных данных приложение не запустится. `/health` и `/health/live` доступны без пароля;
все остальные пути, включая фотографии и `/health/ready`, требуют входа.

Перед обновлением остановите контейнер и перенесите права существующих данных. UID и GID контейнера — 10001:

```sh
docker compose stop
chmod 600 .env
mkdir -p data
sudo chown -R 10001:10001 data
sudo find data -type d -exec chmod 700 {} +
sudo find data -type f -exec chmod 600 {} +
docker compose up -d --build
```

В контейнере создаются закрытые файлы благодаря umask 077. Для отката остановите новый контейнер, восстановите
предыдущую версию кода и при необходимости владельца каталога данных, затем пересоберите контейнер. Не удаляйте
Telegram session при откате.

После десяти неудачных входов за минуту источник временно ограничивается. Для запросов страницы и готовности
действует общий лимит 60 в минуту. Ограничения хранятся в памяти одного рабочего процесса и сбрасываются при
перезапуске; за HTTPS-прокси все клиенты учитываются как один источник. Это базовая защита, а не замена firewall.
