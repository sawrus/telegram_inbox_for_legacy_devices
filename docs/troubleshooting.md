# Диагностика

## Сервис не открывается

Проверьте контейнеры:

```bash
docker compose ps
docker compose logs -f
```

Проверьте IP Orange Pi:

```bash
hostname -I
```

Проверьте liveness отдельно от Telegram:

```bash
curl -i http://127.0.0.1:8080/health/live
```

Ответ `200` означает, что Flask/Gunicorn отвечает. Затем проверьте Telegram readiness:

```bash
curl -i http://127.0.0.1:8080/health/ready
```

Ответ `503` от readiness или главной страницы означает, что Telegram session либо MTProto временно недоступны.
Проверьте сеть, авторизацию session и логи контейнера. Сообщения исключений Telegram намеренно не выводятся пользователю
и не записываются в лог целиком, чтобы не раскрывать номера телефонов, данные session или upstream-детали.

Если сеть медленная, можно изменить общий deadline в допустимых пределах:

```env
TELEGRAM_PAGE_TIMEOUT_SECONDS=15
```

Допустимы значения строго больше `0` и не больше `20`. После изменения пересоздайте контейнер.

Полный список чатов имеет отдельный короткий бюджет `TELEGRAM_DIALOG_LIST_TIMEOUT_SECONDS` (по умолчанию `3`, допустимый
диапазон `(0, 5]`). Если он истекает, сервис автоматически пробует загрузить только два выбранных чата в оставшееся время
общего deadline. Увеличивать этот бюджет обычно не требуется; повторный `503` означает, что не завершился и fallback.

После успешного получения списка выбранных чатов панели загружаются независимо в пределах того же общего deadline.
Если Telegram не отвечает только для одной панели, рабочая панель остаётся видимой, проблемная показывает локальное
безопасное сообщение, а страница отвечает `200`. Глобальный `503` означает, что не удалось получить ни полный список,
ни fallback-summary выбранных чатов.

## Ошибка TELEGRAM_API_ID или TELEGRAM_API_HASH

Проверьте `.env` и перезапустите контейнер:

```bash
docker compose up -d
```

## Telegram session is not authorized

Запустите первичную авторизацию:

```bash
docker compose run --rm telegram-inbox python scripts/init_telegram_session.py
```

## Пустой список сообщений

Сервис показывает входящие и исходящие сообщения выбранных чатов. Если список пустой, проверьте выбранный чат,
увеличьте `MESSAGE_LIMIT` в `.env` или убедитесь, что Telegram session имеет доступ к этому диалогу.

Для bot-user диалогов приложение использует точечный `GetPeerDialogs`, потому что Telegram может оставлять `GetHistory`
без ответа для таких peer. Правая панель показывает самое свежее сообщение с Telegram entities; обычные пользовательские
диалоги продолжают загружать полную историю.
После первой успешной загрузки сервис хранит последние результаты выбранных панелей в памяти процесса. Если очередной
30-секундный refresh получает временную сетевую/RPC-ошибку, пользователь продолжает видеть эти сообщения; в логе появляется
`telegram_pane_stale`. Кэш сбрасывается при перезапуске контейнера и снова заполняется первым успешным запросом.
Для Channel/supergroup сервис автоматически использует ограниченное окно ID вместо зависающей пакетной истории Telethon.
Если в этом окне много удалённых ID, сообщений может быть меньше `MESSAGE_LIMIT`; personal/user чаты продолжают использовать
обычный iterator.

## Ошибка MESSAGE_TIMEZONE

Укажите IANA-имя часового пояса, например:

```env
MESSAGE_TIMEZONE=Europe/Samara
```

После изменения `.env` перезапустите контейнер:

```bash
docker compose up -d
```
