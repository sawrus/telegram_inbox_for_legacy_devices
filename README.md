# Telegram Inbox для локальной сети

Простой Flask-сервис для просмотра сообщений из Telegram через MTProto. Проект рассчитан на запуск внутри домашней сети на Orange Pi Zero 2 с Ubuntu ARM и Docker Compose.

## Возможности

- просмотр двух Telegram-чатов на одном экране;
- мгновенное переключение левого и правого чата через отдельные dropdown;
- просмотр входящих и исходящих сообщений выбранных чатов;
- безопасное отображение Telegram HTML/entities, включая выделение, код, цитаты и абсолютные ссылки;
- показ фото-сообщений прямо в ленте с локальным кэшированием;
- компактный `media`-плейсхолдер для остальных нетекстовых сообщений;
- независимая прокрутка левой и правой панели с закреплённым выбором чата;
- отображение времени сообщений в заданном часовом поясе;
- автообновление страницы через обычный HTML meta refresh;
- фронтенд без SPA-фреймворков, совместимый с iPad Safari iOS 12;
- развёртывание через Docker Compose;
- первичная авторизация Telegram session отдельным скриптом.

## Безопасность

Сервис требует имя пользователя и пароль для просмотра чатов и фотографий. По умолчанию HTTP не шифрует пароль и сообщения: используйте только доверенную домашнюю сеть и не публикуйте порт в интернет. Для шифрования доступен [необязательный HTTPS](docs/https.md). Telegram session-файл даёт доступ к аккаунту, поэтому каталог `data/` нельзя коммитить или передавать третьим лицам.

## Быстрый старт на Orange Pi

```bash
git clone <repo-url>
cd test_codex
cp .env.example .env
nano .env
```

Получите `api_id` и `api_hash` на <https://my.telegram.org>, затем укажите их в `.env`.
Задайте непустые `INBOX_USERNAME` и длинный случайный `INBOX_PASSWORD` в `.env` и ограничьте доступ к файлу: `chmod 600 .env`. Имя пользователя не должно содержать двоеточие.

Подготовьте каталог для непривилегированного контейнера (UID/GID 10001):

```bash
mkdir -p data
sudo chown -R 10001:10001 data
sudo find data -type d -exec chmod 700 {} +
sudo find data -type f -exec chmod 600 {} +
```

Создайте Telegram session:

```bash
docker compose run --rm telegram-inbox python scripts/init_telegram_session.py
```

Запустите сервис:

```bash
docker compose up -d --build
```

Откройте с iPad в той же сети:

```text
http://<orange-pi-ip>:8080
```

## Настройки

Основные переменные окружения описаны в `.env.example`:

- `TELEGRAM_API_ID` — числовой API ID Telegram;
- `INBOX_USERNAME`, `INBOX_PASSWORD` — обязательные учётные данные для входа;
- `TELEGRAM_API_HASH` — API hash Telegram;
- `TELEGRAM_SESSION_NAME` — имя session-файла в `/data`;
- `TELEGRAM_PAGE_TIMEOUT_SECONDS` — общий лимит времени на загрузку списка чатов и обеих панелей, по умолчанию `10`; допустимо строго больше `0` и не больше `20` секунд;
- `TELEGRAM_DIALOG_LIST_TIMEOUT_SECONDS` — короткий бюджет полного списка чатов, по умолчанию `3`; допустимо строго больше `0` и не больше `5` секунд;
- `FLASK_SECRET_KEY` — произвольная секретная строка Flask;
- `REFRESH_SECONDS` — интервал автообновления страницы сообщений, по умолчанию `60` секунд;
- `MESSAGE_LIMIT` — максимальное число последних сообщений для чтения;
- `MESSAGE_TIMEZONE` — часовой пояс отображения сообщений, по умолчанию `Europe/Samara`;
- `MEDIA_CACHE_DIR` — каталог локального кэша изображений, по умолчанию `/data/media`;
- `MEDIA_CACHE_LIMIT_BYTES` — лимит кэша изображений в байтах, по умолчанию `1073741824` (`1 GB`);
- `LEFT_CHAT_ID` — чат, выбранный в левой панели при открытии `/`;
- `RIGHT_CHAT_ID` — чат, выбранный в правой панели при открытии `/`.
- `PINNED_CHATS` — дополнительные варианты, всегда доступные в обоих dropdown, в формате
  `chat_id:title;chat_id:title`.

## Проверки состояния

- `GET /health` и `GET /health/live` — liveness процесса без обращения к Telegram;
- `GET /health/ready` — ограниченная по времени проверка готовности Telegram session, возвращающая `200` или `503`.

Проверка готовности требует авторизации; liveness остаётся открытой для Docker.

Если полный список чатов не успевает загрузиться за короткий бюджет, страница пытается получить только два выбранных чата
и продолжает работу в пределах общего deadline. Если Telegram не отвечает и на fallback, `/` возвращает отрисованную
страницу с HTTP `503`, а не необработанный `500`.

Загрузка страницы использует изолированные авторизованные Telegram-соединения: истории левой и правой панелей читаются
последовательно, а одинаковый chat id — один раз. Ошибка одной истории остаётся внутри соответствующей панели. Текст Telegram сначала
преобразуется из entities, затем очищается закреплённым Bleach allowlist; сырой HTML из сообщения не исполняется.
После первой успешной загрузки краткий сбой Telegram на автообновлении не заменяет панель ошибкой: приложение показывает
последние успешно загруженные сообщения до следующего удачного refresh.
Для bot-user история загружается через Telegram `messages.Search`, поэтому панель показывает до `MESSAGE_LIMIT`, а не
только последнее уведомление; точечный запрос последнего сообщения используется лишь при временном сбое Search.
Обычные пользовательские чаты, включая «Любимая», загружаются через стандартную историю и заменяют предыдущий снимок
кэша; bot-режим определяется только по Telegram bot-признаку, а не по общему типу `InputPeerUser`.
Выбранные панели читаются последовательно через одну Telegram-сессию: параллельные RPC для этих bot-user peer могут
оставлять Search без ответа.
Процесс использует временные рабочие копии авторизованного session-файла и один event loop. Обычные чаты/dialogs получают
свежее короткоживущее MTProto-соединение на каждый HTTP refresh, а bot-history использует отдельное постоянное соединение.
Поэтому зависшее состояние Telethon или reconnect bot Search не замораживают личные чаты.
После Search timeout circuit breaker на 60 секунд переключает обе bot-user панели на быстрый fallback, чтобы автообновление
не создавало бесконечный цикл переподключений; следующая попытка полной истории выполняется после cooldown.
